# 쇼핑몰 진단 v1 검토 — 2026-10-16

대상: reports/diagnostics/shop-v1/report.json. 개발용 CSV 13개 6,409행. 모든 입력 해시와 진단 항목의 원문/레코드 대응을 재확인했다. 평가용 정답은 읽지 않았으며 탐지 정밀도·재현율 평가는 아니다. 엔진·설정·CSV는 변경하지 않았다.

## 판정

진단은 명시된 규칙 위반을 포착했지만, 표준 표기 차이와 의미 손상을 같은 warning으로 표시해 우선순위가 흐려진다. 5,331은 오류 데이터 수가 아니라 중복 가능한 진단 이벤트 수다.

## 경고 분류 근거

- 날짜 1,577: `%Y-%m-%d %H:%M:%S%z` 또는 `%Y/%m/%d %H:%M:%S%z`로 실제 파싱 성공. 연월일과 시간대가 명확한 표기 차이다.
- 금액 1,227: 쉼표 천 단위와 선택적 원 단위 접미사만 있는 정수 표현. 숫자를 임의로 추출하지 않고 전체 문자열 규칙으로 확인했다. 예: `35,000`, `44,000 원`.
- 전화 256: 공백·괄호·하이픈만 제거하면 `010` 뒤 숫자 8자리. 표준화 후보이며 실사용 번호 여부 검증은 아니다.
- 남은 10: 모호한 날짜 1, 불완전 전화 2, 동일 행 중복 참여 6, 참조 불일치 1. 중복 참여 6은 아래 키 중복 12에 포함되어 별개 문제로 합산하지 않는다.

## 사람이 확인해야 할 사례

레코드는 CSV 헤더를 제외한 1부터 시작한다.

| 위치 | 원문 | 판단 |

| customers 1 / 고객명 | 빈 문자열 | 필수값 위반 |
| customers 1 / 휴대폰 | 010-1063 | 자리 부족, 추측 복원 금지 |

중복 키 6그룹: customers CUS000002, orders ORD000004, order_items ITM000010은 각각 동일한 행 2개다. customers CUS000005는 고객명이, orders ORD000005는 배송요청이, order_items ITM000011은 수량 1/2가 충돌한다. 정책 없이 대표 행을 선택하거나 삭제하면 안 된다.

## 정상값을 오류로 보지 않을 것

- 빈 실패코드 687개는 실패가 아닌 결제 상태였고, 빈 취소일시 650개는 취소가 아닌 주문 상태였다. 이러한 빈칸은 정상이다. 빈 값 전체를 오류로 세지 않는다.
- NULL/없음/N/A 후보 139개는 상세주소·배송요청·이메일·휴대폰의 허용된 결측 표현이다. 컬럼 규칙에 따른 표현 통일 대상으로 본다.
- 바깥 공백 90개는 고객명 52·브랜드 22·상품명 16으로, 기존 정책의 trim 대상이다.

## 후속 권장

1. 정상 관측 / 표준화 후보 / 업무 규칙 위반 / 사람 검토로 결과를 나눈다.
2. 중복은 그룹 단위와 참여 행 수를 함께 표시하며 동일/충돌을 구분한다.
3. 정상 빈값은 컬럼 요약으로 보여주고 조건 위반만 강조한다.
4. 수량×단가−할인액, 주문 합계, 거래 시간 순서 등 미구현 업무 규칙을 추가한다. 현재 경고가 타당하다는 사실만으로 모든 오류를 탐지했다고 주장하지 않는다.
