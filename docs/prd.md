## 1. 배경과 문제

규칙 없이 여러 사람이 각자 작성한 파일을 모아 하나의 표로 만드는 일은 커머스·물류 운영에서 흔하다. 주문 담당자, 거래처, 운송사가 보내는 CSV·엑셀은 같은 정보를 서로 다르게 적는다.

| 문제 | 예시 | 결과 |
|---|---|---|
| 표기가 제각각 | 전화번호 `01012345678` / `010 1234 5678` / `+82 10-…`, 금액 `12,000원` / `₩12000`, 결측 `NULL` / `없음` / `N/A` | 같은 값이 다른 값으로 집계됨 |
| 컬럼 이름·순서가 다름 | `주문번호` / `Order Id` / `order_no` | 파일을 합칠 때마다 손으로 맞춤 |
| 값은 정상인데 서로 안 맞음 | 주문 금액 ≠ 상세 합계, 배송 완료 시각이 출고보다 빠름 | 형식 검사로는 안 잡히고 지표가 틀어짐 |
| 양식이 예고 없이 바뀜 | 컬럼 추가·삭제, 자료형 변경 | 반복 집계가 조용히 깨짐 |
| 개인정보가 섞여 있음 | 고객 전화·이메일·주소 | 공유·보고 전에 손으로 가려야 함 |
| 정리 과정이 남지 않음 | 누가 무엇을 왜 바꿨는지 모름 | 오류가 나도 원인을 추적·되돌리기 어려움 |

수작업으로 맞추면 시간이 들고, 일괄 자동 수정은 정상값까지 바꾸거나 모호한 값을 추측으로 채울 위험이 있다.

## 2. 제품 한 문장

**여러 사람이 제각각 만든 CSV·엑셀을 받아, 표준 형식으로 정리할 수 있는 것과 사람이 확인해야 할 것을 근거와 함께 나누고, 사용자가 화면에서 승인한 변경만 원본을 보존한 채 적용하는 도구.**

작업명은 "데이터 전처리 자동화"로 쓴다. 도구 이름은 정하지 않았다(문서·구현에 영향 없음).

## 3. 목표와 비목표

**목표**
1. 처음 보는 파일도 표준 컬럼에 연결하고, 형식 차이는 승인 후 일괄 표준화한다.
2. 값 하나의 형식뿐 아니라 테이블 사이의 업무 정합성까지 검사해 사람이 볼 곳을 좁혀 준다.
3. 한 번 승인한 규칙을 다음 파일에 재사용해 반복 검토를 줄이고, 그 효과를 숫자로 보여 준다.
4. 모든 변경을 추적·되돌릴 수 있게 하고, 원본은 절대 바꾸지 않는다.
5. 데이터 품질을 점수와 추이로 보여 주고, 공유 전 개인정보를 사용자가 확정한 방식으로 가린다.
6. 가상 벤치마크에서 새 고객·거래와 새 입력 표현에 대한 성능을 측정하고, 주장마다 근거를 남긴다.

**비목표 (이번에 하지 않음)**
- 실제 고객 데이터 처리, 실제 업무 효과 주장(시간 절감 등은 가상 데이터 측정치로만 표현)
- 같은 고객으로 보이는 행의 자동 병합, 근거 없는 값 추측·복원, 행 자동 삭제
- OCR·스캔 PDF·메일 본문 파싱, 외부 쇼핑몰·ERP 연동
- 여러 사용자 동시 사용·로그인·권한 관리·검토 담당자 배정, 외부 공개 호스팅
- 범용 규칙 편집 화면(규칙은 분석가가 설정 파일로 관리)
- 실데이터 정기 수집·알림, DB 적재 출력 (후속 확장)

## 4. 사용자

| 구분 | 사용자 | 하는 일 | 필요한 것 |
|---|---|---|---|
| 주 사용자 | **운영 담당자** — 주문·출고·반품 파일을 거래처·담당자에게서 받아 취합·보고하는 사람. 엑셀은 쓰지만 코드는 쓰지 않음 | 매주 파일을 받아 합치고, 이상한 값을 확인하고, 정리된 표를 보고에 씀 | 코드 없이 화면에서 끝나는 흐름, 바뀌는 값의 전후 비교, 실수했을 때 되돌리기 |
| 보조 사용자 | **데이터 분석가** — 규칙과 품질 기준을 정하는 사람 | 표준 스키마·정합성 규칙·마스킹 기준을 설정 파일로 미리 정하고 품질 추이를 관리 | 규칙을 설정 파일로 관리, 품질 점수·변경 이력 조회 |

분석가가 스키마와 JSON 규칙을 미리 설정한 상태에서 운영 담당자가 코드 없이 사용하는 범위다. "코드 없이 S1~S5 완료"가 범용 규칙 편집 화면까지 요구하는 뜻은 아니다.

**실행 형태:** 한 사람이 자기 컴퓨터에서 실행하는 로컬 웹 서비스. 로그인 없음.

## 5. 핵심 시나리오

진단·미리보기·승인·실행·다운로드는 모든 시나리오가 함께 쓰는 공통 흐름이다(기능을 시나리오마다 따로 만들지 않는다).

**S1. 처음 받은 파일 정리**
운영 담당자가 새 거래처의 주문 파일을 올린다 → 도구가 컬럼을 표준 컬럼에 연결하고, 확신이 낮은 연결은 확인을 요청한다(확인 전에는 그 컬럼에 기대는 검사를 진행하지 않는다) → 진단 결과를 기존 엔진의 네 분류(정상 관측 / 표준화 후보 / 업무 규칙 위반 / 사람 검토 필요)로 만들고, 화면 요약에는 조치가 필요한 세 분류를 보여 준다 → 담당자가 변경 미리보기(셀 단위 전후)를 보고 승인·제외한다 → 승인한 변경만 적용한 새 파일과 변경 내역을 내려받는다.

승인해도 엔진 검증은 건너뛰지 않는다. 같은 셀에 미해결 위반·검토 문제가 있는 후보는 보류한다. 실행 전후 재검증에 실패하면 결과를 발행하지 않으며, 실패한 부분 산출물은 다운로드 결과로 주지 않는다. "완료(기존 문제 남음)"와 "실행 실패"를 화면에서 구분한다.

**S2. 매주 같은 곳에서 오는 파일 반복 정리**
지난번 재사용 규칙으로 승인한 규칙을 다음 파일의 후보로 적용한다 → 지난번과 컬럼·자료형·값 범위가 달라졌으면 먼저 경고한다(스키마 변경 감지) → 새로 나타난 표기·스키마 변경·검증 실패는 기존 승인으로 처리하지 않고 검토를 요청한다 → **같은 출처·스키마·패턴이어도 실행마다 최종 확인 버튼을 눌러야 적용된다** → 첫 파일 대비 검토 건수가 얼마나 줄었는지 보여 준다.

**S3. 여러 담당자의 엑셀을 하나로 합치기**
담당자별 엑셀(여러 파일·여러 시트)을 한 번에 올린다 → 시트·파일을 대상 표준 테이블별로 분류·매핑하고, 같은 테이블의 파일끼리 통합한다 → 주문·주문상세·출고처럼 서로 다른 테이블은 키와 업무 규칙으로 연결해 정합성(주문 금액과 상세 합계, 출고 수량과 주문 수량, 시간 순서 등)을 검사하고, 어긋난 행 묶음을 수정 없이 검토 대상으로 보여 준다.
- 참조 파일이나 필수 컬럼이 없어 검사할 수 없는 경우는 "검사 불가"로 표시하고 실제 참조 오류와 구분한다.
- 통합한 뒤에도 원본 파일·시트·레코드 번호·컬럼 위치를 추적한다. 중복될 수 있는 업무 PK만으로 원본을 연결하지 않는다.
- 첫 버전은 시트당 표 하나·머리글 한 줄을 지원한다. 병합 셀·다중 머리글·수식 셀 등 지원하지 않는 구조는 위치와 이유를 보여 주고, 조용히 누락하거나 추정해서 변환하지 않는다. 셀을 문자열로 읽어도 엑셀에서 이미 사라진 앞자리 0이나 원래 식별자를 되살릴 수 있다고 보장하지 않는다.

**S4. 공유 전 개인정보 가리기와 품질 보고**
도구가 개인정보로 보이는 컬럼을 근거와 함께 제안한다(제안일 뿐이며 확인 없이 기본 마스킹을 실행하지 않는다) → 사용자가 그대로 / 제외 / 컬럼 추가 / 가리는 방식 변경을 정한다 → 공유용 결과와 품질 리포트를 내려받는다.
- 로컬 내부 기록(변경 내역·전후 진단)에는 원문을 보존한다. 공유용 다운로드와 HTML 리포트의 예시·변경 내역에는 승인한 마스킹을 똑같이 적용한다.
- 마스킹 결과는 원본이나 정제 결과를 덮어쓰지 않는 별도 출력이다.
- "마스킹 완료"를 "모든 개인정보 제거"로 표시하지 않는다.
- 품질 점수(완전성·유효성·일관성·유일성)에는 어떤 결과 버전·규칙 기준인지 표시한다. 실행하지 않은 검사를 정상 점수로 처리하지 않으며, 품질 점수를 정답 일치율이나 개인정보 탐지 완전성으로 표현하지 않는다.

**S5. 잘못 승인한 변경 되돌리기**
실행 이력에서 이전 결과를 고른다 → 이전 결과를 새 복원 버전으로 남기거나 활성 버전을 바꾼다. 과거 결과와 승인 기록은 지우지 않고, 되돌린 기록도 이력에 남는다.
- **결과 되돌리기와 재사용 규칙 승인 취소는 분리한다.** 결과를 되돌려도 재사용 규칙의 앞으로의 적용 승인은 그대로이며, 규칙 승인 취소는 별도 동작이다.
- 이미 내려받은 파일을 회수·복원하지는 않는다.

## 7. 지켜야 할 원칙

1. **원본 불변** — 입력 파일과 원본 값은 바꾸지 않고, 결과는 항상 새 버전으로 만든다. 기존 결과 폴더를 덮어쓰지 않는다.
2. **승인한 것만 적용** — 표준화는 사용자가 승인한 변경만 실행한다. 이번 실행에 대한 승인과 재사용 규칙에 대한 승인을 구분한다. 재사용 범위와 규칙 버전을 사용자가 확인한 규칙만 다음 파일의 후보가 되고, 적용은 실행마다 최종 확인을 거친다. 승인해도 엔진 검증은 건너뛰지 않는다.
3. **추측하지 않는다** — 잘린 전화번호, 모호한 날짜, 수량 0, 합계 불일치는 고치지 않고 근거와 함께 검토로 보낸다.
4. **모든 변경을 추적** — 파일·시트·레코드 번호·컬럼·원본값·변경값·규칙·이유·실행 버전을 남긴다.
5. **AI는 제안만** — 미리 정의된 변환 중에서만 제안하고, 검증을 통과한 제안만 보여 주며, 확신이 낮으면 보류한다. AI 자체 확신도만으로 실행하지 않는다.
6. **개인정보는 로컬에서** — 데이터와 AI 처리를 외부로 보내지 않는다. 공유용 출력에는 승인한 마스킹을 일관되게 적용한다.
7. **평가 격리** — `docs/benchmark.md`의 격리 계약을 따른다. 웹 API·로컬 AI·보고서 생성도 서비스 범위에 포함하며, 정답(`evaluation_private/`, `deliverables/evaluation-answers.zip`)과 정상 기준 데이터·생성기·검증 보고서는 채점기만 읽는다. GitHub 비공개 여부와 서비스의 정답 접근 차단은 별개다.

## 8. 성공 기준

모든 수치는 가상 벤치마크 기준이며 실제 업무 효과가 아니다. "처음 보는 데이터"는 새 고객·거래와 새 입력 표현에 대한 평가이며, 상품 기준표를 공유하므로 새 상품 카탈로그나 실제 현업 파일 전반으로 일반화한 결과가 아니다.

**평가 시점**
- 목표 수치는 개발셋·개발용 시나리오의 사전 측정으로 정하고, 최종 평가를 실행하기 전에 고정한다.
- 최종 평가는 P0·P1·AI 비교 조건까지 개발셋으로 모두 완성한 뒤 한 번에 한다(규민님 결정). "한 번"은 미리 정한 비교 조건(규칙만 / AI 포함)을 정해진 절차로 측정하고, 결과를 본 뒤에는 튜닝하지 않는다는 뜻이다.
- 평가 결과를 보고 규칙·임계값·프롬프트·모델을 조정했다면 같은 평가셋을 "미사용 평가"로 부르지 않는다. 중간에 평가셋을 실행했다면 그 이후 버전에도 같다. 기술적 실행 실패로 다시 돌린 것과 결과를 본 뒤의 튜닝은 구분해 기록한다.

**반드시 지킬 조건 (0건)**
- 승인 없이 바뀐 셀, 원본 파일·기존 결과 폴더 변경, 검토 대상(review) 사례의 자동 덮어쓰기·행 삭제
- 서비스 범위 코드의 평가 정답 참조
- 같은 입력·같은 규칙으로 다시 실행했을 때 데이터·의미 있는 진단·변경 결과가 달라지는 경우(실행 ID·시각·폴더는 달라도 됨)
- 정제된 결과에 같은 규칙을 다시 적용했을 때 추가 변경이 생기는 경우(멱등성)

**기능 완성 기준**
- 분석가가 설정을 마친 상태에서, 시나리오 S1~S5를 코드 없이 화면에서 끝까지 수행할 수 있다.

**측정 항목** (세부 공식·분모는 ④ 품질·평가 명세가 정본)
- 헤더 매핑과 셀 표준화는 따로 집계한다. 자동 매핑의 정확도·보류율과 사용자 확인 후 최종 결과를 구분하며, 사람이 고친 결과로 자동 매핑 성능을 주장하지 않는다.
- 개발용에 있던 표현과 새 표현은 `docs/benchmark.md`의 `pattern_group` 기준으로 나누고, 총계와 행동별·표현별 결과를 함께 보고한다.
- 검토 대상은 "검토가 필요하다고 알렸는가(탐지)"와 "원문을 보존했는가(보존)"를 따로 측정한다. review에는 복원 정답이 없으므로 숨은 원값으로 복원 정확도를 채점하지 않는다.
- 정상값 오수정은 명시된 유지(keep) 사례뿐 아니라 baseline·row-lineage로 전체 비변경 대상 셀을 검사한다. 값을 바꾼 것과 정상값을 오류로 판단한 것을 나눠 보고하고, 여러 진단 이벤트를 셀 수·오류 수로 그대로 합산하지 않는다.
- 정합성 검사는 어떤 주입 사례를 어떤 진단으로 찾으면 성공인지 연결 기준을 정해 측정한다. 정답에 없는 파생 경고를 모두 오탐으로 채점하지 않고, 규칙별 진단 정답이 없는 동안에는 탐지 정밀도를 확정 수치로 주장하지 않는다. 새 정합성 규칙의 수용 테스트와 최종 평가용 정답 설계는 구분한다.
- 규칙 재사용 효과는 입력 규모·패턴 구성·검토 단위를 맞춘 조건에서 검토 건수 감소를 측정하고, 오수정·검토 탐지 지표와 함께 보고한다.
- 처리 시간은 엔진 처리 시간과 사용자 검토·수정 포함 시간을 구분한다. 수작업과 비교한다면 `docs/project-plan.md`의 별도 유사 난이도 파일·학습 효과 통제 조건을 따른다.
- AI 제안의 규칙만 대비 효과(매핑 정확도·검토 건수·처리 시간)는 AI 구현이 재확인된 경우에만 쓰는 조건부 기준이다.

## 9. 제약과 가정

- 데이터: 가상 쇼핑몰(모아마켓) 13개 테이블과 개발·평가용 오염 데이터, 창고 재고 예제. 실데이터 없음.
- 실행: 1인 로컬 실행, 로그인 없음, 외부 공개 호스팅 없음.
- 입력: 지정 인코딩의 CSV, xlsx(시트당 표 하나·머리글 한 줄). 메모리에 올라가는 소규모 파일.
- 기술: Python 엔진·FastAPI·React(TypeScript)·SQLite. 세부는 ③ 기술 설계서.
- 재현: 서비스 실행은 고정된 CSV와 `data/manifest.json` 해시로 재현한다. 가상 데이터 생성기는 Codex 번들 모듈에 의존해 다른 환경에서 재실행되지 않으며, 생성기를 옮길지는 공개 준비 때 규민님이 정한다.
