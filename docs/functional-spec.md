## 1. 공통 개념

| 개념 | 정의 |
|---|---|
| 출처(source) | 같은 거래처·담당자·운송사에서 반복해서 오는 파일 계열. 사용자가 이름을 붙여 만든다(예: "A운송사 주간 출고"). |
| 양식(template) | 출처 안에서 같은 표준 테이블로 매핑되는 파일의 원래 헤더 구성. 한 출처에 양식이 다른 파일이 섞일 수 있다. |
| 비교·재사용 단위 | **출처 + 표준 테이블 + 양식.** 스키마 변경 감지(F10)와 재사용 규칙(F09)은 이 단위로만 적용되며, 같은 출처라도 다른 양식으로 넘어가지 않는다. |
| 업로드 묶음(batch) | 한 번에 올린 파일들. |
| 실행 대상 | 묶음 중 사용자가 확정한 파일·시트 목록. 구조 오류·지원 불가·사용자 제외 항목은 빠지며, 빠진 항목은 실행 기록에 남는다. |
| 실행(run) | 실행 대상에 대해 매핑 → 진단 → 미리보기·승인 → 적용을 한 번 거친 시도. 실패한 시도도 기록으로 남고, 재시도는 새 실행이다. |
| 결과 버전 | 성공한 실행이 만든 정제 결과·변경 내역·전후 진단과, 그때 쓴 매핑·설정·승인의 참조 묶음. 덧붙이기만 하고 지우거나 덮어쓰지 않는다. |
| 설정 세트 | 분석가가 관리하는 표준 스키마·진단 설정·별칭 사전·정합성 규칙·개인정보 기준·마스킹 기본값(파일). 화면에서 편집하지 않으며, 실행마다 사용한 버전(해시)을 기록한다. |
| 논리 컬럼 | 표준 스키마의 컬럼. 매핑 결과와 진단 설정은 모두 논리 컬럼으로 연결된다(F04 연결 계약). |
| 재사용 규칙 | 사용자가 "다음에도 쓰겠다"고 승인한 매핑·표준화 결정. 비교·재사용 단위별·버전별로 저장하며, 다음 실행에서는 미리 선택된 후보일 뿐이다. |
| 승인 3종 | ① 구조 승인: 실행 대상·테이블 분류·헤더 매핑 확정 ② 실행 승인: 이번 실행의 셀 값 변경 적용(실행마다 최종 확인 버튼, PRD 11절) ③ 재사용 규칙 승인. 셋은 따로 기록한다. |
| 원본 위치 | 업로드 항목 식별자(같은 이름 파일을 두 번 올려도 구별)·파일·시트·레코드 번호(헤더 다음 행이 1)와, CSV는 물리 줄 범위, 엑셀은 셀 좌표·원래 컬럼 이름. 통합·정제 후에도 모든 셀이 이 위치로 돌아간다. |

**실행 상태** (실행 하나는 한 번에 하나의 상태)

| 상태 | 뜻 | 사용자에게 보이는 것 |
|---|---|---|
| 업로드됨 | 파일을 받고 원본을 보관함 | 파일 목록, 읽기 결과, 제외 항목 |
| 확인 필요 | 실행 대상·스키마 변경·매핑 중 확정되지 않은 것이 있음 | 해당 확인 화면 |
| 진단 완료 | 검사가 실행됨(데이터 정상 판정이 아님) | 진단 요약 |
| 승인 대기 | 변경 미리보기 준비됨 | 미리보기 화면 |
| 완료 | 결과 발행, 남은 위반·검토 없음 | 결과·다운로드 |
| 완료(문제 남음) | 결과 발행, 기존 위반·검토가 남음 | 결과·남은 문제 목록 |
| 실패 | 설정·입력·검증·실행 실패. 결과 미발행 | 실패 이유·신규 문제, 실패 진단 리포트만 다운로드 |

**검사 완전성** (상태와 별개로 진단·결과에 붙는 표시)
- **전체 검사:** 켜 둔 검사가 모두 실행됨.
- **부분 검사:** 필수 컬럼 없음·참조 대상 제외·매핑 제외·규칙 꺼짐 등으로 일부 검사를 건너뜀. 건너뛴 검사와 이유를 항상 함께 보여 주며, 위반·실패 건수에 포함하지 않는다. 묶음 중 제외된 파일이 있으면 "업로드 전체 처리"처럼 보이지 않게 표시한다.

## 3. 기능 명세

### F01. 파일 업로드·CSV 읽기·원본 보관 (P0)

- **목적:** 입력을 그대로 보관하고, 이후 모든 처리가 원본을 바꾸지 않게 한다.
- **입력:** CSV 1개 이상, 출처(기존 선택 또는 새로 만들기), 선택 사항으로 인코딩·구분자.
- **동작:**
  1. 업로드 파일을 바이트 그대로 보관하고 SHA-256과 업로드 항목 식별자를 기록한다. 이름이 같은 파일도 다른 항목으로 구별한다.
  2. 모든 셀을 문자열로 읽는다(앞자리 0, 문자열 `NULL`, 빈 문자열과 공백 구분 보존 — 기존 엔진 계약).
  3. 헤더 빈칸·중복 헤더·행별 열 개수 불일치는 구조 오류로 기록한다.
- **출력:** 파일 목록(이름·크기·해시·행 수·헤더), 읽기 결과(성공/구조 오류와 위치).
- **예외·보류:** 구조 오류 파일은 실행 대상에서 빠지며, 이유와 함께 실행 기록에 남는다(F03 실행 대상 확정).
- **승인 지점:** 없음(실행 대상 확정은 F03).
- **수용 기준**
  - AC-01-1 보관한 원본의 해시가 업로드 파일과 같고, 이후 어떤 단계도 원본을 수정하지 않는다.
  - AC-01-2 `007`, `NULL`, 빈 문자열, 공백만 있는 값이 읽기 후에도 서로 구분된다.
  - AC-01-3 구조 오류는 파일·레코드 번호·이유와 함께 표시되고, 그 파일은 실행 대상에 들어가지 않는다.
  - AC-01-4 이름이 같은 파일 두 개를 올리면 두 항목으로 구별되어 각각 추적된다.
  - AC-01-5 출처 없이 업로드할 수 없다(새로 만들기 허용).

### F02. 엑셀 입력·여러 파일 통합 (P1)

- **목적:** 여러 담당자의 엑셀·CSV를 표준 테이블별로 모아 하나로 합친다.
- **지원 입력 조건(첫 버전):** xlsx, 시트당 표 하나, 첫 행이 머리글 한 줄(PRD 11절).
- **동작:**
  1. 각 시트를 하나의 표로 읽는다. 셀은 엑셀 표시 형식이 아닌 **저장값**을 문자열로 읽고, 원래 셀 자료형(텍스트·숫자·날짜 등)을 함께 기록한다.
  2. 병합 셀·수식 셀처럼 명시적으로 식별되는 구조, 그리고 정해 둔 구조 오류 테스트 파일의 유형(빈 머리글 열 등)을 감지하면 "지원하지 않는 구조"로 시트 이름·셀 좌표·이유를 표시하고 그 시트를 실행 대상에서 뺀다. 판단이 모호한 구조는 사용자 확인 또는 "지원 불가"로 보낸다. 조용히 누락하거나 추정해서 변환하지 않는다.
  3. F03에서 같은 표준 테이블로 매핑된 시트·파일끼리 행을 이어 붙인다. 컬럼 순서·이름 차이는 매핑으로 해결한다.
  4. 통합 후에도 모든 행에 원본 위치를 붙인다(엑셀은 셀 좌표, CSV는 물리 줄 범위 — 엑셀에 CSV 줄 번호를 억지로 부여하지 않음).
- **날짜·시각 셀:** 저장값과 원래 자료형을 보존한다. **시간대가 없는 날짜·시각은 해석하지 않고 사람 검토로 보낸다(규민님 결정 Q8 = A안, 10절).** 이미 엑셀에서 사라진 앞자리 0이나 정밀도를 되살린다고 보장하지 않는다.
- **출력:** 표준 테이블별 통합 결과(원본 위치 포함), 시트별 처리 결과(통합/제외와 이유).
- **예외·보류:**
  - 서로 다른 파일의 업무 PK가 겹쳐도 행을 빼지 않는다. 모든 행을 남기고 병합·덮어쓰기 없이 중복 그룹으로 진단한다(F04 유일성). 업무 PK만으로 원본을 연결하지 않는다.
  - 표준 테이블에 매핑되지 않은 시트는 "미분류"로 남기고 통합하지 않는다.
- **승인 지점:** 실행 대상·테이블 분류 확인(F03 구조 승인).
- **수용 기준**
  - AC-02-1 시트 2개·파일 2개를 같은 표준 테이블로 통합하면 행 수가 실행 대상 파일·시트의 합계와 같고, 모든 행이 원래 파일·시트·셀 좌표로 추적된다.
  - AC-02-2 정해 둔 구조 오류 테스트 파일(병합 셀·수식 셀·빈 머리글 열)의 시트는 통합되지 않고, 시트 이름·셀 좌표·이유가 표시된다.
  - AC-02-3 텍스트 셀 `00123`은 `00123`으로 읽히고, 숫자 셀 `123`에 앞자리 0을 추정해 붙이지 않는다.
  - AC-02-4 서로 다른 파일의 같은 PK 행은 모두 남고 중복 그룹으로 보고된다.
  - AC-02-5 시간대가 없는 날짜·시각 셀은 표준화 후보가 되지 않고 사람 검토로 분류된다.

### F03. 실행 대상 확정·테이블 분류·컬럼 매핑 (P0)

- **목적:** 실행 대상을 확정하고, 처음 보는 파일·시트를 표준 테이블에 분류하고, 컬럼을 표준 컬럼에 일대일로 연결한다.
- **입력:** F01·F02의 표, 표준 스키마(`schema.json`), 별칭 사전, 해당 비교·재사용 단위의 재사용 규칙(F09).
- **동작:**
  1. **실행 대상 확정:** 읽기 성공 파일·시트 목록과 제외 항목(이유 포함)을 보여 주고, 사용자가 대상을 확정한다.
  2. **테이블 분류:** 파일·시트 이름과 헤더 구성을 표준 테이블과 비교해 후보 테이블과 근거를 제시한다.
  3. **컬럼 매핑:** 헤더 이름 정규화(공백·대소문자·구분 기호) 후 표준 컬럼 후보를 만들고 근거와 확신 등급을 낸다. **정확히 일치하거나 승인된 별칭과 일치할 때만 "자동 제안"이며, 정규화 후 충돌하거나 유사 이름·값 모양으로 추정한 연결은 모두 "확인 필요"다(Q3).**
  4. 일대일 위반(두 컬럼이 같은 표준 컬럼 후보)·필수 표준 컬럼 누락·표준에 없는 추가 컬럼을 표시한다.
  5. 사용자가 확인·수정한 결과를 이번 실행의 매핑으로 확정한다(구조 승인). 자동 제안 결과와 최종 결과를 따로 기록한다.
  6. 같은 비교·재사용 단위의 이전 매핑과 달라진 점(논리 매핑 변화)과 재사용 규칙 영향을 이 단계에서 보여 준다(F10에서 넘어온 항목). 선택지: 기존 재사용 규칙 유지 / 이번 실행만 새 매핑 / 새 재사용 규칙 버전 승인.
- **판정 규칙**

| 상황 | 처리 |
|---|---|
| 확인 필요·일대일 위반이 남음 | 다음 단계로 못 감 |
| 추가 컬럼을 "미매핑·대상 제외"로 확정 | 원문 보존·프로파일링만 하고 진단하지 않음 |
| 필수 표준 컬럼이 실제로 없음 | 매핑 충돌과 구분. 관련 검사를 건너뛴 "부분 검사"로 진단은 보여 주되, 그 테이블은 결과 발행 대상이 아님(7절) |
| 실행 대상에서 뺀 파일 때문에 참조 대상이 없음 | 관련 참조·정합성 검사를 "부분 검사"로 표시(위반으로 세지 않음) |

- **출력:** 실행 대상 목록, 테이블별 매핑 표(원래 이름 → 표준 이름, 근거, 확신 등급, 자동/사용자 확인), 미매핑·제외 컬럼, 누락 필수 컬럼.
- **승인 지점:** 구조 승인(실행 대상·테이블 분류·매핑 확정).
- **수용 기준**
  - AC-03-1 개발용으로 따로 만든 테스트 입력(영문 별칭·컬럼 순서 변경)과 개발용 한글 헤더 파일이 같은 표준 컬럼으로 연결된다. 최종 평가셋은 이 검증에 쓰지 않으며, 서비스는 정답 매핑을 읽지 않는다.
  - AC-03-2 자동 제안 결과와 사용자 확인 후 최종 결과가 따로 저장된다.
  - AC-03-3 확인 필요·일대일 위반이 남아 있으면 진단으로 넘어가지 않는다.
  - AC-03-4 필수 컬럼이 없는 테이블은 건너뛴 검사와 이유가 표시되고, 위반·실패 건수에 포함되지 않으며, 결과 발행 대상이 아니다.
  - AC-03-5 매핑을 바꾸면 이전 진단·미리보기·실행 승인이 무효가 되고 다시 진단한다(B3 계약, 6절).

### F04. 진단(네 분류)·논리 컬럼 연결 (P0)

- **목적:** 매핑된 데이터를 기존 엔진으로 검사하고 결과를 네 분류로 보여 준다.
- **논리 컬럼 연결 계약:** 현재 진단 설정(`config/shop-diagnostics.json`)은 개발용 한글 헤더(`고객번호`, `휴대폰` 등)로 작성돼 있다. 매핑 결과와 진단 설정을 같은 논리 컬럼에 연결해, 어떤 원래 헤더로 들어온 데이터에도 같은 규칙이 실행되게 한다. 컬럼 규칙뿐 아니라 `required_if`·`unique`·`references`가 가리키는 컬럼도 같은 방식으로 연결한다. 원본 설정 파일과 원본 데이터는 바꾸지 않는다. 연결 구현은 ③에서 정한다.
- **동작:** 기존 엔진(`docs/diagnostics.md`)을 실행한다 — 셀 단위(필수·허용값·패턴·타입·범위·조건부 필수), 유일성, 참조, 중복 행, 결측 후보, 표준화 후보 제안.
- **표준화 지원 범위:**
  - 기존 엔진: krw_integer(쉼표·`원`), kr_mobile(공백·괄호·하이픈), iso_datetime(시간대가 명시된 두 형식), 비교 정규화.
  - **P0 확장(규민님 결정 Q11):** 정규화 정책 문서에 명시돼 있지만 엔진에 없는 변환(예: 명시적 `+82` 국가번호, `₩` 기호)을 정책 항목별로 대조해 구현한다. 근거는 서비스에 제공되는 공개 정책 문서이며, 평가셋 결과를 보고 추가한 것이 아니라는 기록을 남긴다.
  - 정책에도 없고 엔진도 지원하지 않는 표현은 표준화하지 않고 사람 검토로 남긴다.
  - 시간대가 없는 날짜·시각은 표준화 후보로 만들지 않는다(Q8 = A안).
- **출력:**
  - 네 분류 집계(정상 관측 / 표준화 후보 / 업무 규칙 위반 / 사람 검토 필요). 화면 요약은 조치가 필요한 세 분류를 앞에, 정상 관측은 접어서 보여 준다.
  - 항목 목록: 테이블·원본 위치·논리 컬럼·원래 컬럼 이름·원문·규칙 코드·분류·근거·제안값.
  - 중복 그룹(동일 행/키 충돌), 검사 완전성(전체/부분)과 건너뛴 검사의 이유.
- **예외·보류:** 진단 건수를 오류 셀 수·오류율로 표시하지 않는다(한 셀에 여러 진단). "검사 완료"를 "데이터 정상"으로 표시하지 않는다.
- **승인 지점:** 없음.
- **수용 기준**
  - AC-04-1 같은 논리 입력·같은 설정이면 원래 헤더 이름·순서와 관계없이 적용된 규칙과 진단 결과(분류·규칙 코드·원본 위치)가 같다.
  - AC-04-2 한글 헤더·영문 별칭·컬럼 순서가 다른 개발용 테스트 입력에서 필수·조건부 필수·유일성·참조 검사가 실제로 실행되며, 검사 누락을 정상으로 통과시키지 않는다.
  - AC-04-3 부분 검사이면 건너뛴 검사와 이유가 표시되고, 품질 점수(F12)에서 정상으로 처리되지 않는다.
  - AC-04-4 각 항목에서 원본 위치로 이동해 원문을 볼 수 있다.
  - AC-04-5 P0 확장 변환은 정책 항목별 테스트(정상 변환·변환하면 안 되는 값)를 통과하고, 정책 근거가 기록된다.

### F05. 테이블 간 업무 정합성 검사 (P1)

- **목적:** 값 하나는 정상이지만 서로 맞춰 보면 어긋나는 행 묶음을 찾는다.
- **입력:** 매핑 확정된 여러 표준 테이블, 정합성 규칙 설정(분석가 관리).
- **첫 버전 규칙 (Q6, 10개 안팎)** — 규칙마다 입력·관계·적용 상태·계산 가능 조건을 둔다. 문법은 ③.

| 종류 | 규칙 | 적용 상태·예외(`docs/business-rules.md`) |
|---|---|---|
| 행 내 계산 | `line_total = quantity × unit_price − discount_amount` | 값이 모두 파싱 가능할 때만 |
| 테이블 간 합계 | `order_total = Σ order_items.line_total + shipping_fee` | 주문 상세가 연결될 때만. 부모 키 중복이면 계산 불가 |
| 시간 순서 | 결제 성공 시각 ≤ 출고 시각 | 성공 결제 기준. 출고 준비 상태의 빈 출고 시각은 정상 |
| 시간 순서 | `shipped_at ≤ delivered_at` | 배송 완료 건만. 빈 시각은 상태에 따라 정상 |
| 시간 순서 | 배송 완료 시각 ≤ 반품 접수 시각 | 배송 완료된 출고에 연결된 반품만 |
| 상태 조건 | 결제 완료·처리 중·완료 주문 → 성공 결제 정확히 1건 | 결제 시도가 여러 번이어도 성공은 최대 1건 |
| 상태 조건 | 결제 대기 주문 → 성공 결제·출고 없음 | 경과 일수만으로 위반 판정하지 않음 |
| 누적 상한 | 출고 수량 합계 ≤ 주문 수량 | 취소된 출고 수량 제외 |
| 누적 상한 | 반품 수량 합계 ≤ 출고 수량 | 거절·취소된 반품 제외 |
| 누적 상한 | 성공 환불 합계 ≤ 원결제액 | 실패 환불 제외. 반품 없는 출고 전 전체 취소 환불 허용 |

- **계산 기준 3가지 (Q7):**
  1. **원문 기준** — 입력 그대로 계산.
  2. **가상 기준** — 표준화 후보를 모두 적용했다고 가정한 계산. 참고용이며, 위반을 해결한 것으로 확정하지 않는다.
  3. **승인 기준** — 사용자의 현재 승인 선택만 적용한 계산. 사용자가 선택을 바꾸면 갱신한다.
  결과마다 어떤 기준인지 표시한다. **최종 판정은 F07에서 실제 결과로 다시 검사한 것이다.**
- **결과 구분:** 실제 계산 모순(업무 규칙 위반) / 파싱 불가·연결 모호·근거 부족(검사 불가 — 부분 검사).
- **출력:** 위반 묶음(규칙·관련 테이블·관련 행의 원본 위치·계산값과 기대값·계산 기준), 규칙별 검사 상태.
- **예외·보류:**
  - 자동 수정·제안값을 만들지 않는다(어느 값이 틀렸는지 알 수 없음).
  - 부모 키 중복·참조 누락으로 연결을 확정할 수 없으면 임의의 행을 고르거나 조인으로 부풀려진 합계를 모순으로 확정하지 않는다.
  - 필요한 입력이 없으면 "합계 0 = 정상"으로 통과시키지 않고 검사 불가로 표시한다.
- **보류 연결:** 위반 묶음에 속한 셀이라고 해서 모든 표준화 후보를 막지는 않는다. 위반 계산에 직접 쓰이는 셀의 후보만 보류 대상으로 표시하고, 같은 행 중복은 다른 안전한 셀 표준화를 막지 않는다는 기존 예외(`docs/cleaning.md`)를 유지한다. 보류 규칙의 세부 대응표는 ③에서 정한다.
- **승인 지점:** 없음(검토 대상 표시만).
- **수용 기준**
  - AC-05-1 규칙마다 고의 오류 테스트 데이터에서 위반 묶음을 찾고, 개발 테스트 도구가 정상 기준 데이터로 만든 입력 복사본에서는 0건이다(서비스가 `data/clean`을 직접 읽지 않음).
  - AC-05-2 정상 예외(빈 출고 시각, 취소 출고, 거절 반품, 실패 환불, 출고 전 전체 취소 환불)는 위반이 아니다.
  - AC-05-3 참조 부족·부모 키 중복·파싱 불가 입력은 위반이 아니라 검사 불가로 표시되며, 정상 0건으로 통과시키지 않는다.
  - AC-05-4 위반 묶음은 관련된 모든 행의 원본 위치를 포함하고, 어떤 값도 바꾸지 않는다.
  - AC-05-5 금액 표기 후보를 고르거나 빼면 승인 기준 계산이 바뀌고, 결과 발행 판정은 실제 승인 결과의 재검사로 한다.
  - AC-05-6 규칙마다 켜고 끌 수 있고, 꺼진 규칙은 "미실행"으로 표시되어 정상 처리되지 않는다.

### F06. 변경 미리보기·승인 (P0)

- **목적:** 표준화 후보를 적용 전에 보여 주고, 사용자가 고른 것만 실행되게 한다.
- **입력:** F04 표준화 후보, F05 보류 표시, 해당 단위의 재사용 규칙(F09).
- **동작:**
  1. 후보를 **규칙 묶음**(테이블 × 논리 컬럼 × 변환 종류) 단위로 보여 준다. 각 묶음에 건수·전후 예시·근거를 표시한다. 건수는 진단 이벤트가 아니라 **고유 변경 셀** 기준이다(Q4).
  2. 사용자는 묶음 단위로 승인·제외하고, 묶음 안의 개별 셀을 제외할 수 있다.
  3. 같은 셀에 미해결 위반·검토가 있는 후보는 "보류"로 표시하며 승인할 수 없다. 서로 충돌하는 제안은 실행 오류로 처리한다(기존 정제 계약).
  4. 선택을 바꿀 때마다 F05 승인 기준 계산·보류·적용 건수를 갱신한다.
  5. 묶음마다 "다음에도 이 규칙 사용"을 선택할 수 있다 — 재사용 규칙 승인(F09), 실행 승인과 별개.
  6. 최종 확인 화면에서 적용 셀 수·제외 수·보류 수를 보여 주고 "실행"을 누르면 F07로 넘어간다.
- **승인 무효화:** 실행 대상·매핑·설정 세트(해시)·후보가 바뀌면 이전 미리보기와 실행 승인은 무효이며, 영향받는 진단·미리보기를 다시 만든 뒤 다시 승인받는다. 실행 준비 중 재사용 규칙 승인을 취소하면 그 규칙으로 미리 선택된 항목을 해제하고 다시 확인받는다.
- **출력:** 실행 승인 목록(묶음·개별 셀 제외 포함)과 그때의 입력·매핑·설정 해시, 재사용 규칙 승인 목록.
- **예외·보류:** 검토 대상·업무 위반은 변경 대상으로 나오지 않는다(표시만).
- **승인 지점:** 실행 승인(최종 확인 버튼), 재사용 규칙 승인(선택).
- **수용 기준**
  - AC-06-1 승인하지 않은 묶음·제외한 셀은 결과에서 바뀌지 않는다.
  - AC-06-2 보류 후보는 승인 버튼이 비활성이고 이유가 표시된다.
  - AC-06-3 재사용 규칙으로 미리 선택된 후보도 실행마다 최종 확인을 거쳐야 적용된다.
  - AC-06-4 미리보기 뒤 매핑·설정·실행 대상을 바꾸면 예전 승인으로 실행되지 않는다.
  - AC-06-5 성공한 실행에서 최종 확인 화면의 적용 셀 수가 변경 내역의 고유 변경 셀 수와 같다.

### F07. 실행·결과 발행·다운로드 (P0, 기존 정제 + 확장)

- **목적:** 승인한 변경만 적용해 새 결과 버전을 만들고, 검증을 통과한 결과만 내려받게 한다.
- **입력:** 실행 승인 목록과 그때의 입력·매핑·설정 해시.
- **동작:**
  1. 승인 때의 해시와 현재 입력·매핑·설정이 같은지 확인한다. 다르면 실행하지 않고 다시 승인받는다.
  2. 기존 정제 엔진(`docs/cleaning.md`)을 승인 목록으로 제한해 실행한다 — 원본 재진단 → 승인 후보 적용 → 임시 결과 재진단(F04, 켜 둔 F05 포함) → 신규 위반·검토·중복이 생기면 전체 실패 → 전체 셀 대조·해시 확인 → 발행.
  3. 실행 대상 전체에 대해 결과를 한꺼번에 발행하거나 실패한다(부분 발행 없음). 필수 컬럼 누락 등으로 발행 대상이 아닌 테이블이 있으면 실행 전에 알린다.
- **감사 기준:** 구조 변환(헤더 매핑·통합)과 셀 값 변경을 따로 기록한다. 행 수 보존은 실행 대상 파일·시트 합계 기준, 값 대조는 원본 위치 기준이다. 빈 문자열과 논리 null은 출력 CSV만으로 구분되지 않으며 변경 내역 JSON에서 구분한다(기존 계약).
- **출력:**
  - 내부 결과("원문 포함 — 내부 검토용" 표시): 정제 CSV(표준 컬럼 이름, UTF-8), 변경 내역(CSV·JSON), 전후 진단, 보류 목록, manifest.
  - 공유용 결과는 F11 마스킹 확정 후에만 만든다(Q9).
  - 실패 시: 실패 진단 리포트만 내려받을 수 있고 결과 데이터는 없다.
  - xlsx 출력은 이번 범위가 아니다(후속 제안).
- **예외·보류:** 실패 후 재시도는 실패 기록을 남기고 새 실행으로 한다. 조건이 바뀌었으면 다시 진단·승인한다. "완료"와 "완료(문제 남음)"를 구분해 표시한다.
- **승인 지점:** F06의 실행 승인으로 시작.
- **수용 기준**
  - AC-07-1 결과의 바뀐 셀이 모두 승인 목록에 있고, 승인 목록 외 셀은 원문과 같다(원본 위치 기준 전체 셀 대조).
  - AC-07-2 재검증에서 신규 위반이 생기면 상태가 "실패"이고, 결과 데이터 다운로드가 없으며, 실패 진단 리포트만 있다.
  - AC-07-3 같은 입력·같은 설정·같은 승인으로 다시 실행하면 데이터·변경 내역·검사 범위가 같다(실행 ID·시각·폴더 제외).
  - AC-07-4 결과 버전에 **같은 유효 규칙·같은 적용 범위**를 다시 적용하면 변경 셀이 0이다(멱등성). 승인 범위를 넓힌 실행은 이 조건이 아니다.
  - AC-07-5 기존 결과 폴더는 덮어쓰지 않는다.
  - AC-07-6 승인 이후 설정 파일이 바뀌면 실행되지 않는다.

### F08. 버전 이력·되돌리기 (P1)

- **목적:** 잘못 승인한 결과를 되돌리되, 과거 기록은 지우지 않는다.
- **동작:**
  1. 출처별 결과 버전을 시간순으로 보여 준다(실행 승인 내용·상태·품질 점수 요약·검사 범위).
  2. "이 버전으로 되돌리기"는 **새 복원 버전**을 만든다(Q5). 복원 버전은 선택한 버전의 데이터와, 당시 매핑·설정·진단·변경 내역·품질 점수를 **참조**로 가진다.
  3. "복원 이벤트"는 원래 정제 변경 내역과 구분해 기록한다. 현재 규칙으로 다시 계산한 점수를 과거 점수처럼 붙이지 않는다.
  4. 되돌리기는 결과에만 적용된다. 재사용 규칙 승인은 바뀌지 않으며, 규칙 승인 취소는 F09에서 따로 한다(PRD 11절).
  5. 복원 버전을 다른 마스킹 설정으로 공유하려면 F11 확인을 다시 거친다.
- **예외·보류:** 실패한 실행은 복원 대상이 아니다. 이미 내려받은 파일은 회수하지 않는다(화면 안내). 스키마 변경 감지(F10)의 비교 기준에는 복원 이벤트를 포함하지 않는다 — 오래된 결과를 복원해도 새 업로드의 비교 기준이 되돌아가지 않는다.
- **승인 지점:** 되돌리기 확인.
- **수용 기준**
  - AC-08-1 되돌리기 후에도 모든 과거 버전과 승인 기록이 그대로 남는다.
  - AC-08-2 복원 버전의 데이터 해시가 선택한 버전과 같고, 당시 매핑·설정·진단·점수를 그대로 조회할 수 있다.
  - AC-08-3 되돌리기는 재사용 규칙 승인 목록을 바꾸지 않는다.
  - AC-08-4 복원 이후의 다음 업로드는 마지막 업로드 실행 기준으로 스키마 변경을 비교한다.

### F09. 재사용 규칙·검토 감소 측정 (P1)

- **목적:** 한 번 승인한 결정을 다음 파일의 후보로 재사용해 반복 검토를 줄이고, 그 효과를 측정한다.
- **동작:**
  1. 재사용 규칙은 비교·재사용 단위(출처 + 표준 테이블 + 양식)별로 버전과 함께 저장한다(매핑 결정, 표준화 묶음).
  2. 같은 단위의 다음 묶음에서 같은 패턴인 후보를 "재사용 규칙 적용 후보"로 미리 선택해 둔다. 실행은 F06 최종 확인 후에만 한다.
  3. 새 패턴·스키마 변경·검증 실패는 재사용 대상이 아니며 일반 검토로 보낸다. 스키마 변경을 확인했다고 재사용 규칙을 자동으로 다시 승인하지 않는다(F03 6번 선택지).
  4. 재사용 규칙 화면에서 규칙을 보고 승인을 취소할 수 있다(편집은 설정 파일에서).
  5. 측정: 실행마다 "사용자가 판단해야 했던 항목 수"(확인 필요 매핑 + 미리 선택되지 않은 표준화 묶음 + 검토 대상)를 기록한다. 감소율의 비교 조건(입력 규모·패턴 구성·검토 단위)은 ④.
- **예외·보류:** 승인 취소는 이후 실행부터 적용되며 과거 결과를 바꾸지 않는다.
- **승인 지점:** 재사용 규칙 승인(F06), 승인 취소.
- **수용 기준**
  - AC-09-1 재사용 규칙은 같은 비교·재사용 단위에만 후보로 나타난다. 같은 출처의 다른 양식에는 나타나지 않는다.
  - AC-09-2 스키마 변경이나 새 패턴이 있는 후보에는 재사용 표시가 붙지 않는다.
  - AC-09-3 재사용 후보도 최종 확인 없이는 적용되지 않는다.
  - AC-09-4 승인 취소 후 다음 실행에서 해당 규칙이 후보로 나오지 않고, 과거 결과 버전은 바뀌지 않는다.

### F10. 스키마 변경 감지 (P1)

- **목적:** 같은 단위의 새 파일이 지난번과 달라졌으면 먼저 알린다.
- **비교 기준:** 같은 비교·재사용 단위의 마지막 업로드 실행(복원 이벤트 제외). 첫 실행은 "기준 생성"으로 표시한다.
- **두 단계로 나눈다:**

| 단계 | 화면 | 확인하는 변화 |
|---|---|---|
| 매핑 전 | SC03 | 원래 헤더 추가·삭제, 이름 변경 의심(사라진 컬럼과 새 컬럼의 값 모양이 비슷함 — 확정하지 않음), 값 모양 변화(숫자만/하이픈/통화 기호 등의 분포), 값 범위 변화(최소·최대, 범주 새 값) |
| 매핑 후 | SC04 (F03 6번) | 같은 원래 이름이 다른 표준 컬럼으로 연결되는 등 논리 매핑 변화, 재사용 규칙 영향 |

- **출력:** 변경 목록(종류·테이블·컬럼·이전/이번 요약), 재사용 후보에서 빠진 규칙.
- **예외·보류:** 변화가 있다는 것만 알리며 오류로 판정하지 않는다. 값 범위 변화 판단 기준은 ④.
- **승인 지점:** 매핑 전 변경 확인(확인 전에는 매핑 단계로 못 감).
- **수용 기준**
  - AC-10-1 컬럼 하나를 지우고 하나를 추가한 파일에서 두 변경이 모두 보고된다.
  - AC-10-2 개발용으로 만든 헤더 변경 테스트 입력(한글 → 영문 별칭)을 같은 단위로 올리면 헤더 변경이 보고되고, 매핑이 같아도 재사용 규칙은 F03 선택지를 거친다. 최종 평가셋은 쓰지 않는다.
  - AC-10-3 변경 감지 결과는 어떤 값도 바꾸지 않는다.

### F11. 개인정보 탐지·마스킹 (P1)

- **목적:** 공유용 출력에서 개인정보를 사용자가 확정한 방식으로 가린다.
- **탐지(제안) 대상 (Q2):** 이름(`customer_name`, `recipient_name`), 전화(`phone`, `recipient_phone`), 이메일, 주소(`address_line1`, `address_line2`), 우편번호, **운송장 번호**(`tracking_number` — 배송과 연결되는 식별자), 자유 텍스트(`delivery_memo`, `reason_detail` — "안의 개인정보를 다 찾을 수 없음" 안내). 상품 바코드는 기본 제외. 사용자는 어느 컬럼이든 추가할 수 있다. 법적 개인정보 판정을 자동 확정하지 않는다.
- **기본 방식 (Q1, 사용자가 컬럼마다 바꿀 수 있음):** 이름·이메일·상세 주소·우편번호·자유 텍스트·운송장 번호는 **전체 가림**. 전화는 전체 가림이 기본이며, 사용자가 부분 가림(가운데 4자리)을 고를 수 있다. 주소의 시·군·구만 남기는 처리는 주소 해석이 필요해 이번 기본값에 넣지 않는다. 짧거나 형식이 이상한 값은 부분 가림을 고른 컬럼에서도 전체 가림으로 대체한다(원문 그대로 통과 금지).
- **동작:**
  1. 컬럼 이름 단서와 값 패턴 비율로 후보 컬럼과 근거를 보여 준다(예: "recipient_phone — 값의 98%가 휴대전화 형식"). 확인 없이 마스킹하지 않는다.
  2. 컬럼마다 결정한다: **마스킹** / **마스킹 안 함**(원문 유지) / **공유 파일에서 컬럼 빼기** / 방식 변경, 그리고 컬럼 추가.
  3. 확정한 설정을 결과 버전에 묶어 공유용 출력을 만든다. 적용 대상: 정제 CSV 사본, 변경 전후 값, 남은 문제의 원문, 정합성 묶음 상세, 미매핑 추가 컬럼, 원래 헤더·원본 위치를 통해 보이는 예시, HTML 리포트.
  4. 설정은 비교·재사용 단위별로 저장해 다음 실행에서 제안으로 다시 쓴다(확인은 매번).
- **출력:** 공유용 결과(별도 파일), 마스킹 설정 기록(컬럼별 결정, 탐지/사용자 추가 구분, 결과 버전).
- **예외·보류:** 내부 기록은 원문을 유지한다. 마스킹 결과는 원본·정제 결과를 덮어쓰지 않는다. 설정을 바꿔 다시 만들어도 과거 공유 산출물을 덮어쓰지 않는다. "마스킹 완료"를 "모든 개인정보 제거"로 표시하지 않는다.
- **승인 지점:** 마스킹 설정 확정.
- **수용 기준**
  - AC-11-1 승인한 변환 결과가 모든 공유 출력(위 3번 목록)에 똑같이 적용되고, 승인하지 않은 원래 값이 다른 경로로 나타나지 않는다.
  - AC-11-2 별칭 매핑으로 원래 컬럼 이름과 표준 컬럼 이름이 둘 다 보이는 곳에서도 마스킹이 적용된다(테스트로 확인).
  - AC-11-3 "공유 파일에서 컬럼 빼기"를 고른 컬럼은 공유 CSV에 없고, "마스킹 안 함"을 고른 컬럼은 원문 그대로다.
  - AC-11-4 짧거나 형식이 이상한 값은 정한 대체 처리가 되고 원문으로 나가지 않는다.
  - AC-11-5 내부 결과 버전은 마스킹 전 그대로다.
  - AC-11-6 같은 결과 버전·같은 설정이면 공유용 출력이 같다.

### F12. 데이터 품질 점수·대시보드 (P1)

- **목적:** 결과 버전의 품질을 네 차원 점수와 추이로 보여 준다.
- **기준 데이터 (Q10):** 항상 마스킹 전 내부 결과 버전. 마스킹은 점수 재계산이나 품질 향상으로 세지 않는다.
- **동작:** 테이블·출처·실행별로 완전성·유효성·일관성·유일성 점수를 계산하고 출처별 실행 추이를 그린다. 공식·분모·가중치·부분 검사 점수 산식은 ④.
- **출력:** 점수 카드, 테이블별 표, 실행 추이 차트, 점수마다 계산 기준(결과 버전·설정 버전·검사 범위).
- **예외·보류:** 실행하지 않았거나 검사 불가인 차원은 "측정 안 됨" 또는 범위를 밝힌 부분 점수로 표시하며, 전체 범위를 검사한 점수로 오인되게 하지 않는다. 점수를 정답 일치율·개인정보 탐지 완전성으로 표현하지 않는다.
- **승인 지점:** 없음.
- **수용 기준**
  - AC-12-1 각 점수 옆에 계산 기준(결과 버전·설정 버전·검사 범위)이 표시된다.
  - AC-12-2 검사 범위가 일부인 차원은 전체 범위 점수처럼 표시되지 않는다(정합성 검사를 끈 실행의 일관성 점수 등).
  - AC-12-3 같은 결과 버전·같은 설정·같은 검사 범위면 다시 계산해도 점수가 같다. 설정을 바꿔 다시 계산하면 새 평가 기록이다.

### F13. HTML 결과 리포트 (P1)

- **목적:** 실행 결과를 한 파일로 공유한다.
- **동작:** 한 파일짜리 HTML — 실행 요약(상태·실행 대상·제외 항목·입력 해시), 매핑 표, 네 분류 집계, 정합성 위반 묶음 요약, 적용 변경 예시(전후), 남은 문제, 품질 점수와 계산 기준, 한계 문구(가상 데이터·검사 범위).
- **출력:** 공유용 HTML(F11 마스킹 적용, 마스킹 확정 후에만). 실패한 실행은 실패 진단 리포트만 만든다.
- **수용 기준**
  - AC-13-1 리포트는 외부 파일·네트워크 없이 열린다.
  - AC-13-2 리포트에 AC-11-1 공유 출력 계약이 적용된다.
  - AC-13-3 리포트의 집계가 결과 버전의 진단·변경 내역과 같다.

### F14. 채점기·최종 평가 (P0, 개발 도구)

- **목적:** 정답 대비 성능을 PRD 8절 기준대로 측정한다. 서비스 기능이 아니라 별도 개발 도구다.
- **입력:** 서비스가 만든 결과(매핑 기록·변경 내역·진단·결과 CSV), 정답(`evaluation_private/<split>/`), 평가 조건 정의.
- **동작:**
  1. 서비스 실행과 분리된 명령으로만 실행한다. 정답·정상 기준 데이터·생성기·검증 보고서·정답 ZIP은 채점기만 읽는다.
  2. 행동별(map_column / normalize / review / keep)·`pattern_group`별로 따로 집계한다. 매핑은 자동 제안과 최종 결과를 나눠 잰다. review는 탐지와 보존을 나눠 재며 원값 복원을 요구하지 않는다. 오수정은 baseline·row-lineage로 명시된 keep 외 전체 비변경 셀까지 잰다. 정답에 없는 파생 경고를 일괄 오탐 처리하지 않는다.
  3. 실행 조건(코드 커밋·설정 해시·평가 조건·실행 시각·재시도 사유)을 기록한다.
- **예외·보류:** 개발 중에는 개발셋에만 실행한다. 최종 평가셋은 개발 완료 후 한 번(PRD 8절). 기술적 실패 재시도는 사유와 함께 기록한다.
- **승인 지점:** 최종 평가 실행 전 규민님 확인.
- **수용 기준**
  - AC-14-1 서비스 범위 코드(엔진·API·화면·AI·리포트)가 정답·정상 기준 데이터·생성기·검증 보고서·정답 ZIP에 접근하지 않는다(테스트로 확인, 방식은 ③).
  - AC-14-2 정답 변조·review 복원값 주입·정답의 입력 폴더 유출 같은 개발용 음성 사례에서 오채점·격리 위반을 탐지한다.
  - AC-14-3 보고서가 총계와 행동별·`pattern_group`별·자동/최종 매핑별 결과를 함께 보여 주고, 서로 다른 단위를 하나의 정확도로 합치지 않는다.
  - AC-14-4 같은 결과에 대해 채점 결과가 같다(실행 시각 등 메타데이터 제외).

### F15. AI 제안 (P2) — 구현 전 규민님 재확인

- **원칙:** 로컬 모델만 사용, 미리 정의된 변환·표준 컬럼 중에서만 제안, 엔진 검증을 통과한 제안만 표시, 불확실하면 보류, 제안·채택·거절을 기록, AI 확신도만으로 실행하지 않음. AI 제안은 F03 매핑과 F06 미리보기에 "AI 제안" 표시로만 들어간다.
- **세부 명세:** 구현 착수 전 재확인 후 작성한다(모델·입력 범위·출력 형식·평가 조건).
- **수용 기준(원칙):** AC-15-1 AI를 끈 상태에서 모든 시나리오가 동작한다. AC-15-2 AI 제안도 사용자 승인 없이는 적용되지 않는다. AC-15-3 데이터가 컴퓨터 밖으로 나가지 않는다.

### F16. 재고 예제(웹 포함)·README·GitHub (P0/P1)

## 5. 공통 요구

- **원본 불변·추적:** 모든 결과·진단 항목은 원본 위치로 돌아갈 수 있다.
- **덧붙이기만:** 실행(실패 포함)·결과 버전·승인 3종·되돌리기·규칙 승인 취소 기록은 지우거나 덮어쓰지 않는다.
- **로컬 처리:** 데이터·AI 처리를 외부로 보내지 않는다. 화면은 이 컴퓨터에서만 접속한다.
- **평가 격리:** 서비스 범위 코드는 정답·정상 기준 데이터·생성기·검증 보고서·정답 ZIP을 읽지 않는다(AC-14-1). 개발 테스트는 테스트용 입력 복사본만 서비스에 주고, 정답 대조는 테스트 도구에서 한다. 최종 평가셋은 화면 AC 검증에 쓰지 않는다.
- **오류 표시:** 실패·검사 불가·보류에는 항상 이유와 위치를 함께 보여 준다. 진단 건수를 오류율로 표시하지 않는다.
- **언어:** 화면은 한국어. 규칙 코드·컬럼 이름은 원문 그대로.
- **규모:** 메모리에 올라가는 소규모 파일(개발셋 13개 테이블·약 6,400행 수준). 응답 시간 목표는 ④.

## 7. 결과 발행 조건

결과 버전은 아래를 모두 만족할 때만 발행한다.
1. 실행 대상 전체의 구조 승인과 실행 승인이 현재 입력·매핑·설정 해시와 일치한다.
2. 발행 대상 테이블은 필수 표준 컬럼이 모두 매핑돼 있다(그렇지 않은 테이블은 실행 전에 발행 대상에서 빠졌음을 알린다).
3. 재검증에서 신규 위반·검토·중복이 없다.
4. 원본 위치 기준 전체 셀 대조와 해시 확인을 통과한다.
